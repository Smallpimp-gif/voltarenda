# Вольтаренда — правила проекта

Аренда/выкуп электровелосипедов. Прод — Cloudflare Workers (OpenNext),
данные в KV (локально — файлы `data/<key>.json`). Деплой сайта:
`npm run cf:deploy`; крон-напоминаний: `npm run cf:deploy-cron`.

## Учёт денег (денежная модель — соблюдать строго)

### Закупки товара — `lib/purchases.ts`, вкладка «Закупки»

Товар считается **поштучно**. Каждая закупка (партия) обязана хранить:

- **количество** закупленных единиц (`qty`, шт);
- **цену закупки за штуку** (`unitCost`, ₽);
- **доставку** на партию (`delivery`, ₽).

Из этого считается (не хранить — вычислять в `purchaseStats`):

- **вложено** = `qty * unitCost + delivery`;
- **себестоимость единицы** = `вложено / qty`;
- продажи ведутся **частями** (`Sale`: `qty` проданных штук + `revenue` выручка);
- **прибыль** = `выручка − (продано штук × себестоимость единицы)` — считается
  только по проданному;
- **остаток** = `qty − продано`; **«в товаре»** = `остаток × себестоимость` —
  сколько денег «висит» в непроданном.

**Закупка — это НЕ расход.** Деньги вернутся с продажей, поэтому закупки
ведут отдельный P&L и не смешиваются с расходами и с кассой аренды.
Продажу нельзя провести на количество больше остатка.

### Касса «на руках» — `lib/ledger.ts`

«На руках сейчас» = собранные деньги: **аренда + магазин + ручные
корректировки**. **Расход НЕ вычитается** из этой суммы — он показывается
отдельной строкой в разбивке (для учёта), но собранное не уменьшает.
Расход = безвозвратная трата (ремонт, реклама, зарплата, склад).

### Периоды оплаты — `lib/schedule.ts`

У арендатора есть период оплаты `period` ∈ `day | week | month`
(по умолчанию `week`; поле `weekly` = сумма **за период**, `buyoutWeeks` =
число **периодов** до выкупа). Месяц — **строго календарный** (день привязан
к числу заезда, с клампом: 31 янв → 28/29 фев → 31 мар).

⚠️ Логика расчёта дат платежей продублирована в **трёх** местах — при любой
правке менять все три синхронно:

- `lib/schedule.ts` (сайт),
- `bot/lib/schedule.mjs` (grammy-бот),
- `workers/reminders/index.mjs` (cron-воркер напоминаний).

## Проверка

- Типы: `npx tsc --noEmit`.
- Логику модулей удобно гонять реальным кодом через esbuild-бандл
  (`--alias:@=<корень>`, стаб для `@/lib/store`) — не полагаться только на
  ручной клик в браузере.
